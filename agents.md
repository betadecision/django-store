# Agents Guide

## Контекст проєкту

Будуємо інтернет-магазин на Django backend + React frontend.
Проєкт на етапі планування, тому архітектура має бути простою, явною й легкою для змін.

## Правила співпраці

- Людина відповідає за Git і GitHub дії.
- Агент не комітить, не пушить гілки, не відкриває pull request, не мерджить pull request і не змінює GitHub settings без явного прохання.
- Агент може підказувати доречні Git-дії й пояснювати команду, мету та очікуваний результат.
- Агент може дивитися `git status` і `git diff`, щоб розуміти стан workspace.
- Агент уникає небезпечних Git-команд на кшталт `git reset --hard`, `git checkout --` і force push, якщо їх явно не попросили й не підтвердили.

## Як вчимо Git

Коли Git або GitHub доречні, пояснюємо маленькими кроками:

- що змінилось;
- чому це варто зберегти зараз;
- яку команду виконати;
- як перевірити результат;
- якої помилки уникнути.

Базовий workflow:

1. Подивитися стан: `git status`
2. Переглянути зміни: `git diff`
3. Додати потрібні файли: `git add <files>`
4. Закомітити ясно: `git commit -m "Short imperative summary"`
5. Пушити тільки коли людина готова: `git push`

## Інженерні принципи

- Обираємо прості, зрілі й добре підтримувані інструменти.
- Тримаємо межу між backend і frontend явною.
- Додаємо абстракції тільки коли вони зменшують реальне дублювання або прояснюють відповідальність.
- Важливий прогрес, відкриті питання й наступні кроки ведемо в `progress.md`.
- Setup-команди мають бути відтворюваними.
- Тести пишемо близько до поведінки, яку вони перевіряють.

## Поточна домовленість

- Агент може створювати й редагувати локальні файли проєкту.
- Людина практикує Git/GitHub вручну.
- У змістовних точках збереження агент має сказати про це й запропонувати commit message.
